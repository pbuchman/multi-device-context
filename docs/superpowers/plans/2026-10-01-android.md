# Android implementation plan

Approved in conversation on 2026-10-01. Phone via local USB ADB first; DUDU7 acceptance deferred.

## Constraints
- Shared React/TypeScript/Vite UI, current Firestore/storage/backend and Auth0 account identity. Capacitor 8.5.2 Android wrapper; Kotlin native integrations; Auth0.Android 4.1.0, min API26, target/compile36, JDK21.
- Private APK only; no store, FCM, notifications, background service, automatic updater or iOS implementation.
- Bundled assets served from https://localhost; trusted existing MDC_APP_ORIGIN for API and canonical context links. Keep RuntimeConfig strict shape and DesktopBridge v1 backward compatible.
- Foreground realtime, refresh on resume/reconnect, one manual refresh for contexts + selected items + tombstones. Preserve drafts/selection except authoritative deletion. 15s deadline, coalesce calls, ignore late results, do not block reads behind uploads.
- Existing desktop background behavior unchanged. Android stops subscriptions/retry scheduling in background, keeps durable drafts/outbox, resumes eligible work. No promise of offline authenticated cold boot.
- Receive system shares into a new context, preserve existing draft, stable request IDs, durable native inbox acknowledged only after durable outbox transaction. Native input limits32 files/100MiB per share,256MiB inbox; existing text262144 bytes/file100MiB.
- Android text paste/copy, picker/save/share files, touch Send/Paste/Refresh/Settings, keyboard/rotation/back, existing multi-device-context://context/UUID navigation. Auth0 separate com.multidevicecontext.mobile scheme, PKCE, secure credentials; Firebase Auth in memory on mobile.
- One stable local signing key for local debug/release, appId com.multidevicecontext.mobile, versionCode increments, adb install -r. CI test key is not a device update artifact.
